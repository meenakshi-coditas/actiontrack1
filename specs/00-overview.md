# actiontrack — System Overview (SDD root)

Spec-Driven Development order used here: **spec.md → tests.md → plan.md → code + executable tests**, per module.
Every requirement has an ID (e.g. `DT-R3`); every test case in `tests.md` cites the requirement it proves; every test in `test/*.test.js` carries the test-case ID in its name.

## 1. Purpose
Read markdown meeting notes, track action items, draft (never send) follow-up emails.

## 2. Module map

| # | Module | Source | Depends on | Responsibility |
|---|--------|--------|-----------|----------------|
| 1 | dates | `src/dates.js` | – | Resolve due-date phrases to ISO dates relative to a meeting date |
| 2 | parser | `src/parser.js` | dates | Parse one note: header, attendees, checkbox items; detect malformed notes |
| 3 | owners | `src/owners.js` | – | Resolve raw owner strings to people; handle same-first-name ambiguity |
| 4 | store | `src/store.js`, `src/dedupe.js` | owners | Persistence, IDs, duplicate merging, mark-done |
| 5 | ingest | `src/ingest.js` | parser, owners, store | Walk a folder, two-pass ingest, produce report |
| 6 | query | `src/query.js` | owners | Status derivation (open/done/overdue), filters, sorting |
| 7 | followup | `src/followup.js` | query, owners | Build one email per owner; write drafts via a sink (never send) |
| 8 | cli | `src/cli.js`, `bin/actiontrack.js` | all | Four commands + `serve`; exit codes; formatting |
| 9 | api-web | `src/server.js`, `web/` | all | Local REST backend + browser dashboard |

## 3. Assumptions (the pasted brief was truncated; these fill the gaps)
- **A1 Note format**: front matter (`---` block) with `date:` (`YYYY-MM-DD`), `attendees:` (comma list, optional `<email>`), optional `title:`. A header of bare `Date:`/`Attendees:` lines (no `---`) is also accepted.
- **A2 Action items**: Markdown task lines `- [ ] ...` / `- [x] ...` (also `*`, and `-[ ]text` with no space). Items inside fenced code blocks are ignored.
- **A3 Status model**: stored status is `open|done`. `overdue` is **derived**: open and due date strictly before *today*. The three statuses are mutually exclusive (`--status open` excludes overdue).
- **A4 Today** = `--today <date>` flag, else env `ACTIONTRACK_TODAY`, else the system's local date.
- **A5 Followup** targets: `followup <owner>` for one owner, `followup --all` for every owner. Unassigned items are never emailed (reported instead). Ambiguous owners are never emailed (reported instead).
- **A6 Gmail**: the CLI never talks to Gmail. `followup --json` hands reviewed drafts to Claude, which creates them through the Gmail MCP connector using **create_draft only** (never a send tool). `.eml` files (`X-Unsent: 1`) remain the offline fallback. No send code exists in the repo.
- **A7 Storage**: one JSON file, default `./.actiontrack/db.json`, override with `--db` or `ACTIONTRACK_DB`. Zero third-party dependencies (Node ≥ 18).
- **A8 Sample data**: `notes/` is generated by `scripts/gen-samples.js` (deterministic): 32 notes, 4 long/messy, 6 malformed.

## 4. Shared data model

```
Note   { file, date:ISO, title, attendees:[{name,email|null}], items:[RawItem] }
RawItem{ line, slot, checked, ownerRaw|null, task, due:ISO|null, dueRaw|null }
Item   { id:"AT-0001", owner|null, ownerStatus:"resolved|ambiguous|unknown|none",
         candidates:[names], task, due|null, dueRaw|null, status:"open|done",
         doneAt|null, doneBy:"cli|note|null", firstMeeting, lastMeeting,
         sources:[{file,line,slot,meetingDate,checked}] }
Db     { version:1, nextId, items:[Item], people:[{name,email|null}], ingests:[Report] }
```

## 5. Cross-cutting rules
- X1 No module throws on bad *data*; only on bad *usage* (missing folder, unknown id, bad flag).
- X2 Ingest is idempotent: re-ingesting the same folder changes nothing.
- X3 No network access, no email send capability, server binds `127.0.0.1` only.
- X4 All dates are ISO `YYYY-MM-DD`, computed in UTC arithmetic to avoid DST drift.

## 6. Traceability
`specs/<module>/spec.md` (requirements) → `tests.md` (cases) → `test/<module>.test.js` (executable) → `plan.md` (build steps/status).
